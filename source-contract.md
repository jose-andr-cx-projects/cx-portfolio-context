# Organisational sources and publishing contract

## Purpose
This is a **Bitbucket-ready staging snapshot**. When imported into the approved CoM Bitbucket workspace, the organisational repository becomes the working source for its maintained Markdown *where designated*. These files do not certify the current Jira, Confluence or operational status.

| Information | Source and use |
|---|---|
| Versioned project Markdown, decisions and design working drafts | This repository, if approved as the source for that content |
| Endorsed project narrative, formal governance and signed-off decisions | Confluence or published repository output according to the approved project contract |
| Delivery issues, owners, due dates and status | Jira |
| Collaborative designs and journey visuals | Miro, with approved exports where the agent cannot read board objects |
| Discussion and workshop inputs | User-provided approved Teams transcript/notes; a transcript is evidence, not automatically a formal decision |
| Programme overview | CX Portfolio index, a referenced summary rather than a second project management system |

## Update workflow
1. José provides new approved transcript, project information or instruction within the CoM environment.
2. CX Project Companion reads README and exact target file. It distinguishes verified existing material from new evidence and proposals.
3. The agent recommends the smallest next action and optional Miro visual.
4. Prepare a minimal, auditable file change; clarify decisions, owners or conflicts that require approval.
5. Apply through authorised CoM tools after explicit approval. At present native Rovo Bitbucket file edit, commit and branch creation are **not demonstrated**; provide ready-to-apply Markdown instead.
6. Read back the resulting file/commit; update or reconcile published Confluence and Jira records only as appropriate and permitted.
7. Do not claim synchronisation, approval, publication or deployment without evidence.

## Maintenance
- README is the navigation entry point; keep direct paths accurate.
- A decision record records decision **status**: proposed, approved, superseded or open.
- Every material insight should state its source, date and whether it is verified.
- Jira owns work item state; this repository contains only the rationale and link.
- Do not include raw transcripts, personal data, confidential extracts or secrets in the repository by default.
- Do not mirror operational CoM records to personal GitHub or Personal/Strategic OS.

## Import gate
After Bitbucket import, verify permissions, repository identifiers, branches, actual Confluence publishing configuration and Jira mappings. Replace placeholders with verified organisational links. Until then these are candidate contracts, not deployed integration claims.
