## Purpose

Preserve a small, dated record of material movement across CX workstreams so weekly conversations, cross-project coordination and future project-agent experiments can start from a consistent context.

This file is **not** a task tracker, Jira replacement, endorsed decision register or a source of approved project status. Follow the source rules in [README.md](README.md). Confluence, Jira, Bitbucket and other project-specific organisational systems remain authoritative for the material they govern. Strategic OS remains authoritative for private strategic/career interpretation; keep that interpretation out of this repository.

## Weekly operating loop

1. **Before Friday:** Review recent relevant project activity and authoritative sources where available. Compare with the last log entry. Mark claims that come only from chat or GitHub mirrors as **Working / unverified**.
2. **Friday, 9 am:** Prepare Dennis catch-up talking points from significant changes and unresolved questions; use the heading **Strategic direction:** for questions that invite discussion, not for assumed decisions.
3. **After the conversation:** Record material feedback, the agreed next move, and who must confirm it. Do not present an unverified conversation summary as a formally endorsed decision.
4. **Next week:** Carry forward only open items. Close or supersede older signals rather than repeatedly copying the same update.

A scheduled chat briefing does **not**, by itself, update this GitHub file. Any future automatic write-back needs an explicit implementation decision, source checks and human review.

## Guardrails

- No raw customer or controlled organisational data, credentials, identifying case details, or private stakeholder/career commentary.
- Link to source documents rather than copying them. Avoid publishing sensitive meeting notes or unapproved decision records.
- Record a source, date and confidence for substantive status claims.
- Do not infer project completion from GitHub activity alone.
- Update once per week or after a material change; no daily administration requirement.
- If this repeats information already maintained elsewhere without improving Friday decisions, simplify or retire it.
- Future agents may read and propose changes; actual write-back requires an approved workflow and human review.
